# Architecture decisions

The record of every architecture decision and every deliberate difference from the reference
HospitalOS web project. Each entry says what was decided, why, and who approved it. Details live
in the planning documents linked from each entry. Nothing here changes the reference's
requirements silently.

Status values: **Approved** (owner approved), **Proposed** (awaiting approval), **Superseded**.

## Decisions

| ID | Decision | Status | Where |
|---|---|---|---|

| AD-M-002 | Independent backend: Node.js 24, Express 5, TypeScript, Zod, Drizzle ORM, PostgreSQL 17; never Fastify or Prisma | Approved 2026-11-05 (MD-2) | Architecture §1–4 |
| AD-M-003 | Independent database; never connect to, reuse or migrate the reference's backend or database | Approved 2026-11-05 (MD-3) | Architecture §7 |
| AD-M-004 | Releases R1 to R9; all 11 roles and 88 permissions kept | Approved 2026-11-05 (MD-4, MD-9) | Roadmap |
| AD-M-005 | Navigation: Home, Work Queue, Search, Inbox, Profile | Approved 2026-11-05 (MD-6) | Matrix §7 |
| AD-M-006 | The backend owns all data; seeds live in PostgreSQL and reach the app through the API | Approved 2026-11-05 (MD-12) | Architecture §6 |
| AD-M-007 | Seeds and accounts: no default or shared passwords; audited Super Admin bootstrap; demo accounts only in development and test | Approved 2026-11-05 (MD-20) | Architecture §6.3 |
| AD-M-008 | Minimal staff-account administration in R1 | Approved 2026-11-05 (MD-23) | Roadmap 1.2b |
| AD-M-009 | **One canonical shared package, `packages/contracts`** (roles, 88 permissions, API schemas, validation contracts, common types). No `packages/shared`. The backend alone makes authorization decisions | Approved 2026-11-05 (D1, phase 1.1) | Architecture §2 |
| AD-M-010 | **End-of-day job in Release 2**, as an addition beyond the built reference; its schedule, reconciliation, idempotency, recovery and audit rules are reviewed before R2 | Approved 2026-11-05 (D2, phase 1.1) | Workflows §6 |
| AD-M-011 | **Workspace migration in two steps.** Phase 1.1: root npm workspace with `apps/api` and `packages/*` only; `apps/mobile` stays outside with its own lockfile. Phase 1.2: the mobile app joins when it first imports `@hospitalos/contracts`, as its own verified step. Evidence: Expo's `resolveWorkspaceRoot` returns no workspace root for a project left out of the workspace list, so Metro keeps `apps/mobile` as its root | Approved with the phase 1.1 plan | Architecture §2 |
| AD-M-012 | **Migrations:** forward-only SQL files applied by our own runner with SHA-256 checksums and an advisory lock; drizzle-kit only generates SQL for review and never connects to a database | Approved with the phase 1.1 plan | `apps/api/README.md` |
| AD-M-013 | **Database identity guard:** the API refuses any database outside `DATABASE_ALLOWED_NAMES` (only `hospitalos_*` names accepted), any user other than `hos_app`, and any over-privileged user; migrations do the same with `hos_owner` | Approved with the phase 1.1 plan | Architecture §7 |
| AD-M-014 | Local PostgreSQL container is never restarted automatically (`restart: 'no'`) and binds only to `127.0.0.1:5433`; project databases and roles are created by a separate, approved script, not at container start | Approved with the phase 1.1 plan | `docker-compose.yml` |
| AD-M-015 | **Readiness reads migration state:** `hos_app` gets SELECT only on `schema_migrations` (granted by the migration runner) so `/api/ready` can compare recorded migrations with the build. No INSERT, UPDATE, DELETE, TRUNCATE, schema CREATE, ownership or migration rights; verified by database tests | Approved 2026-11-05 (owner, phase 1.1 review) | `apps/api/README.md` |
| AD-M-016 | **CI gates.** API job: every step blocks. Mobile job: typecheck, lint, Prettier and Jest block; the dependency audit blocks on any high or critical advisory not classified in `scripts/mobile-audit-exceptions.json` (each with a review date; critical never exempt; classified ones are printed as warnings); Expo Doctor is report-only until the Expo patch upgrade is approved (KI-9). CI credentials are random per run, never repository secrets | Approved 2026-11-05 (owner, phase 1.1 review) | `.github/workflows/ci.yml`, KI-12 |
| AD-M-017 | **Incoming-link guard (first task of phase 1.2, kept active in production):** every incoming link is checked before Expo Router parses it. Only the app's own scheme (`hospitalos://`) and an explicit allow-list of in-app destinations pass; unknown schemes (`javascript:`, `data:`, `file:`, `intent:`, `http(s):` and others), malformed or over-long URLs and undecodable percent-encoding are sent to a safe screen. Untrusted input can never trigger external navigation. Security tests cover allowed and rejected URLs. No external-link feature is added before the guard exists. Mitigates KI-12 until Expo SDK 58 | Approved 2026-11-06 (owner); implemented in phase 1.2 (`src/features/links/link-guard.ts`, `src/app/+native-intent.ts`, ESLint external-navigation rules) | KI-12 |
| AD-M-018 | **The app reads `@hospitalos/contracts` from source** (TypeScript path, Metro `watchFolders`, Jest mapping) and keeps its own lockfile, instead of joining the npm workspace (AD-M-011 phase-1.2 step). The contracts re-export `z`; the app may not import `zod` directly | Proposed in R1 phase 1.2, awaiting owner review | `apps/mobile/metro.config.js` |
| AD-M-019 | **Development demo workspace kept in R1** (development builds only, no credential, never calls the API, DEMO DATA labels), next to real sign-in. Architecture §5.5 planned to retire it in 1.2; it backs the design tests and stays until the owner retires it | Proposed in R1 phase 1.2, awaiting owner review | `src/features/dev/` |
| AD-M-020 | **No new crypto or mail dependencies:** argon2id from Node 24's built-in `crypto.argon2` (instead of `@node-rs/argon2`), and a loopback-only SMTP client for Mailpit (instead of `nodemailer`). Production email stays R9 | Proposed in R1 phase 1.2, awaiting owner review | `apps/api/src/auth/crypto.ts`, `src/mail/mailer.ts` |
| AD-M-021 | **Queries use Drizzle's `sql` template** (bound parameters) with Zod-parsed rows; tables are created by hand-written forward-only SQL migrations, not Drizzle schema objects | Proposed in R1 phase 1.2, awaiting owner review | `apps/api/src/db/sql.ts` |
| AD-M-022 | **Unauthenticated requests to any `/api/v1` path answer 401**, including unknown paths, so route names aren't discoverable without a session | Proposed in R1 phase 1.2, awaiting owner review | `apps/api/src/app.ts` |
| AD-M-023 | **Opt-in CORS** (`CORS_ORIGINS`, empty by default) so the Expo web build can call a local API in development. Safe with bearer tokens (the API ignores cookies) | Proposed in R1, awaiting owner review | `apps/api/src/middleware/cors.ts` |
| AD-M-024 | **Web token store is memory-only** (no localStorage); Android/iOS keep the refresh token in the keystore | Proposed in R1, awaiting owner review | `apps/mobile/src/services/session/token-store.ts` |
| AD-M-025 | **Windows-first delivery.** One central Windows computer runs the API and PostgreSQL; staff use browsers over the hospital LAN; a single-computer demonstration mode; distributed as a ZIP with `run.bat`, `stop.bat`, setup instructions and source. The Expo mobile app is kept and uses the same API | Approved 2026-11-18 | [Windows architecture](WINDOWS-ARCHITECTURE.md) |
| AD-M-026 | **Browser frontend: React + TypeScript + Vite in `apps/web`**, sharing `packages/contracts`, built to static files that the API serves from its own origin (`WEB_ROOT`, no CORS). The Expo web build stays a fallback demo until `apps/web` reaches R1 parity | Approved 2026-11-18; shell built in W1 | `apps/web`, `apps/api/src/http/static.ts` |
| AD-M-027 | **Bundled portable runtimes on Windows:** Node 24 and PostgreSQL 17 binaries inside the ZIP, pinned by version and SHA-256; PostgreSQL listens on localhost only. Docker Compose remains the development setup on Mac/Linux | Approved 2026-11-18; implementation in W2 | Windows architecture §3 |
| AD-M-028 | **HTTPS is mandatory on the network.** The API refuses to start in production on a non-loopback `HOST` without `TLS_CERT_FILE`/`TLS_KEY_FILE`; TLS 1.2 minimum; plain HTTP only on loopback. The CSP asks browsers to upgrade requests only when the listener is HTTPS. Setup will generate a local hospital CA or import the hospital's certificate (W2) | Approved 2026-11-18; enforcement and listener built in W1 | `apps/api/src/config/env.ts`, `apps/api/src/http/listen.ts` |
| AD-M-029 | **Web session persistence (direction):** httpOnly, Secure, SameSite=Strict refresh cookie for `apps/web` with an Origin/CSRF check, so a page reload keeps the session. Needs a design review and an API change; mobile keeps keystore tokens. Replaces AD-M-024 for `apps/web` once delivered | Approved in principle 2026-11-18; design and build in W3, not implemented | Windows architecture §6 |
| AD-M-030 | **Process model:** console start/stop scripts first. Graceful stop through a separate control listener bound to 127.0.0.1 only, `POST /shutdown` with a fresh random per-run token kept in `CONTROL_TOKEN_FILE` (removed at shutdown). Windows services remain a later option (would revise AD-M-014) | Approved 2026-11-18; control listener built in W1 | `apps/api/src/http/control.ts`, `apps/api/src/cli/stop-server.ts` |
| AD-M-031 | **Database purpose names:** `hospitalos_prod` is required in production and refused outside it; `hospitalos_demo` (single-computer demonstration) is never used in production. Migration and operator targets `demo` and `prod`; demo seeding never targets `prod` | Approved 2026-11-18; built in W1 | `apps/api/src/config/env.ts`, `apps/api/src/cli/seed-demo.ts` |
| AD-M-032 | **Compiled server:** esbuild bundles the server and operator commands into `apps/api/dist` (migrations copied alongside), so an installation runs `node dist/server.js` with no `npm install` and no `tsx` | Approved 2026-11-18; built in W1 | `apps/api/build.mjs` |
| AD-M-034 | **Root dependency audit gate** (`npm run audit` → `scripts/mobile-audit.mjs root`): fails on any high or critical advisory, and always on one in production dependencies (`npm audit --omit=dev`, never excepted). Development-only exceptions use the existing `scripts/mobile-audit-exceptions.json` with `target: "root"`, one package, an allow-list of verified dependents, `devOnly: true` and an `expires` date after which the gate fails automatically. First entry: GHSA-fc5q-39xc-vjpf (`picomatch`, no fixed release), expires 2026-11-25 (KI-26). The mobile gate is unchanged | Approved 2026-11-18 (owner, option B) | `scripts/mobile-audit.mjs`, `scripts/mobile-audit-exceptions.json` |
| AD-M-033 | **Password reset on Windows installations:** administrator-assisted reset (existing `reset-password` command) in R1; a hospital SMTP server with TLS is a later option. The loopback-only SMTP rule is unchanged | Approved 2026-11-18; no code change in W1 | Windows architecture §6 |

## Deliberate differences from the reference

| ID | Difference | Reason | Status |
|---|---|---|---|
| M-ADR-1 | Opaque access token + rotating refresh token (SecureStore) instead of a cookie session with CSRF | A native app has no browser cookie store | Approved (MD-5) |
| M-ADR-2 | Emailed 8-digit code instead of a reset link | No web page for a link to open | Approved (D4) |
| M-ADR-3 | Server-Sent Events kept, authenticated with the bearer token and read with Expo's streaming `fetch` | The browser `EventSource` can't send an `Authorization` header | Approved (D5) |
| M-ADR-4 | Push notifications with preferences and privacy-safe lock-screen text | Staff are often away from the screen | Approved in principle (D5); the outside-service connection needs approval in R7 |
| M-ADR-5 | LiveKit only, no peer-to-peer fallback | Mobile networks rarely connect peer to peer | Approved (D5); infrastructure approved in R8 |
| M-ADR-6 | Own Compose project, network, volume, databases, users, ports and environment files | Run beside the reference without touching it | Approved (MD-13) |
| M-ADR-7 | R1 views receipts and lab reports in the app only; export and sharing deferred | Exported files carry patient data out of the app | Approved (D2 of the review); export design needs its own approval |
| M-ADR-8 | Billing corrections resolved by Finance instead of automatic credit notes | Owner decisions MD-11, D1, D3 | Approved |
| M-ADR-9 | End-of-day job built here although the reference only designed it | It completes time-based states (no-shows, missed follow-ups, prescription closure) | Approved for R2 (AD-M-010) |
